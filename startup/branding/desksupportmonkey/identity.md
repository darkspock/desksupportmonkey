# DeskSupportMonkey — Community Brand Identity

**Date:** 2026-02-24
**Brand type:** Open source community — developer and sysadmin audience

---

## Role in the Dual Brand Strategy

DeskSupportMonkey is the open source, community-facing brand. It is the engine behind DSM Control — the same codebase, the same product, but positioned for a different audience.

**DeskSupportMonkey is for:**
- Developers who want to self-host
- Sysadmins exploring ITAM tools
- Open source contributors
- The build-in-public audience (founders, AI enthusiasts, tech press)
- Self-hosters on r/selfhosted, r/homelab

**DeskSupportMonkey is NOT for:**
- The compliance buyer at a hospital (that's DSM Control)
- The IT manager who needs a "solicitar demo" button (that's DSM Control)
- Press releases or corporate communications (that's DSM Control)

## Content Strategy

DeskSupportMonkey owns the following narratives:

1. **Build in public** — MRR updates, architectural decisions, mistakes, the AI experiment
2. **Open source community** — contributions, self-hosting guides, Docker setup, feature requests
3. **Technical content** — architecture deep dives, DDD patterns, how Claude Code built X feature
4. **The AI-managed company story** — this lives here, not on DSM Control

These narratives drive awareness and community, which feeds into DSM Control's paid funnel:

```
Developer finds DeskSupportMonkey on GitHub
    → Stars the repo, maybe self-hosts
    → Tells their IT manager about it
    → IT manager visits dsmcontrol.com
    → IT manager signs up for cloud version
```
